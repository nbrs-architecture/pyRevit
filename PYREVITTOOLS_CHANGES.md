| 2026-10-29 | `extensions/pyRevitTools.extension/pyRevit.tab/Drawing Set.panel/Sheets.pulldown/Room Data Sheets.pushbutton` | Creates a drawing sheet per room holding any combination of: a floor plan rotated along the room's longest boundary, a reflected ceiling plan, four interior elevations (A-D), two sections cut through the room centre (one horizontal and one vertical to the plan) and an axonometric 3D view. Only the ticked views are created; sheet creation itself is optional, so the tool also works as a "views only" builder. The settings dialog (shared `uiUtils.html` dialog, so it runs on IronPython and CPython alike) covers titleblock, sheet number, titleblock orientation, a view template per view type, the elevation/section/viewport types and an optional prefix for the view names. Plans/RCPs are cropped to the room boundary (falls back to the rotated bounding box when the loop cannot be offset), elevations and sections to the room extent, and everything is placed in an adaptive 4-column grid, then re-aligned because a new viewport is offset by its label. View, sheet and sheet-number collisions are resolved automatically. Self-contained: Revit API + pyrevit only, no `rpw`/`pychilizerLib`, and helpers are reloaded per run because pyRevit caches imported modules for the whole session |
| 2026-10-07 | `extensions/pyRevitTools.extension/pyRevit.tab/Selection.panel/select.stack/Select.pulldown/Select Elements with Manual Override.pushbutton` | Selects every element carrying an element-level graphic override ("Override Graphics in View > By Element") in the active view. Compares each element's `View.GetElementOverrides()` result against a default `OverrideGraphicSettings` across all 16 override channels (colours compared by `IsValid` + RGB, ElementIds by the version-safe `get_elementid_value_func()`), lists the matches with clickable ids, then sets the selection via `revit.get_selection().set_to()`. Only element-level overrides are found - category and view-filter overrides are separate mechanisms - and only elements visible in the active view are scanned, so an override deliberately set to its default value (e.g. transparency 0) is indistinguishable from "never set". Avoids `forms.check_graphicalview` deliberately: that helper only exists in `forms._ipy`, so the tool uses `uidoc.ActiveGraphicalView` and stays engine-agnostic |

## Added Hooks

| Date | Hook path | Description |
|------|-----------|-------------|
| 2026-10-13, fixed 2026-10-30 | `extensions/pyRevitTools.extension/hooks/command-before-exec[ID_FILE_IMPORT].py` | Cancels the "Insert > Import > Import CAD" command unless the active document is a family, so DWG/DXF/DGN/SAT must be linked rather than imported. Uses a command hook rather than a `file-importing` hook because `Application.FileImporting` also fires for Link CAD and `FileImportingEventArgs` exposes no way to tell the two apart. The family check runs before `Cancel` is assigned because `RevitEventArgs.Cancel` is one-way: releasing a cancel throws `InvalidOperationException: Event cannot be un-cancelled!`, which made the hook fail in every family document (import cancelled plus a traceback). Consequence: if the active document cannot be read, the import proceeds. 3DM imports and Link CAD are unaffected; drag-and-drop and direct `Document.Import()` calls bypass the hook |
| 2026-10-13 | `extensions/pyRevitTools.extension/hooks/command-before-exec[ID_OBJECTS_CLOUD].py` | Cancels the "Create a revision cloud" command unless the active view is a drawing sheet, so revision clouds can only be placed on sheets. Uses a command hook rather than `doc-changed` because `Application.DocumentChanged` is a read-only event with no cancel and could only report a cloud that already exists |
